# 리포팅 플레이북 — 계획 / 진행 / 코멘트 / 완료 템플릿

deskG 태스크에 **사람이 읽기 편하게** 리포팅하기 위한 템플릿 모음.
본문은 파일로 저장한 뒤 헬퍼로 넘긴다(`--html-file` / `--body-file`).
(`<스킬>` = 설치된 스킬 폴더 절대경로. 경로 규칙은 `SKILL.md` 헬퍼 사용법 참고.)

- **태스크 본문**은 정화된 리치 HTML을 지원한다(헤딩·목록·강조·코드·링크·이미지·**표·접기·다이어그램**).
  정확한 **허용 태그 목록은 `references/api-reference.md`를 단일 출처**로 삼는다.
  `style`·`class`·`script`는 제거되고, 링크는 `http/https`만.
- **말로 길게 설명하는 대신 그림·표를 쓴다.** 흐름·순서·상태 전이는 다이어그램
  (`<pre data-diagram="mermaid">…</pre>`), 항목 비교·명령 목록은 표가 훨씬 빨리 읽힌다.
  문법·종류는 `api-reference.md`, 예시 모음은 <https://deskg.kr/313>.
- **코멘트**는 **평문**이다. HTML 태그는 그대로 escape되어 글자로 보인다. 줄바꿈은
  유지된다(`pre-wrap`). `@표시이름` 은 멘션으로 강조되고 해당 사용자에게 알림이 간다.
  URL은 자동 링크되지 않는다(참조용 텍스트로만).

---

## 1) 계획 — 태스크 본문 (HTML)

`plan.html`로 저장 후:
```bash
python "<스킬>/scripts/deskg.py" new --title "작업 요약 (2026-07-12)" --html-file plan.html --folder 4
```

```html
<h3>🎯 목표</h3>
<p>무엇을 왜 하는지 1~2문장으로.</p>

<h3>🧩 배경 · 관련</h3>
<ul>
  <li>관련 태스크: <a href="https://deskg.kr/72">#72 deskg ai 스킬</a></li>
  <li>확인한 사실 / 제약 / 근거가 될 기존 정보</li>
</ul>

<h3>🛠 계획</h3>
<ol>
  <li>1단계 — …</li>
  <li>2단계 — …</li>
  <li>3단계 — …</li>
</ol>

<h3>✅ 완료 기준</h3>
<ul>
  <li>이게 되면 끝, 이라고 말할 수 있는 조건</li>
</ul>
```

작성 전 반드시 **관련·중복 태스크를 먼저 검색**한다 — 키워드를 바꿔 2~3번, 후보는
`task {id}`로 상세 본문까지 확인(검색은 제목+본문 프리뷰만 매치, SKILL §0 참고).
이미 있으면 새로 만들지 말고 그 태스크에 이어서 보고한다.

---

## 2) 진행 보고 코멘트 (평문)

> 태스크 **본문 자체가 새 상태로 갱신**될 진전이면 코멘트 대신 **진행 추가(새 버전)** 를 쓴다:
> `python "<스킬>/scripts/deskg.py" progress {id} --html-file prog.html` (SKILL §2). 아래는 본문은 두고
> 스레드에 **진행을 보고**하는 코멘트 템플릿이다.

의미 있는 진전(단계 완료·결정·산출물·방향 전환·블로커 해결)을 보고할 때. `progress.txt`로 저장 후:
```bash
python "<스킬>/scripts/deskg.py" comment 72 --body-file progress.txt
```

```
▶ 진행 — 2단계: 헬퍼 CLI 완성

한 일
• deskg.py 작성(me/tasks/task/folders/new/comment), 본문 파일 입력 지원
• me·tasks·task·folders 실제 호출로 동작 확인

현재 상태
• 읽기 명령 전부 정상, folderId 매핑 확인(개선점=4)

다음
• SKILL.md와 리포팅 템플릿 작성
```

원칙: 헤더 한 줄(`▶ 진행 — 무엇`) + `한 일` + `현재 상태` + `다음`. 길면 불릿으로 쪼갠다.

---

## 3) 코멘트만 — 가벼운 메모 (평문)

진행 보고까지는 아닌 것: 짧은 질문·확인, 사소한 관찰, "따로 처리" 메모, 피드백 확인.
`note.txt`로 저장 후:
```bash
python "<스킬>/scripts/deskg.py" comment 72 --body-file note.txt
```

예시(한 줄~몇 줄이면 충분):
```
📌 완료 상태는 API로 못 바꿔서, 마무리 후 UI에서 '완료'로 바꿔주셔야 합니다.
```
```
❓ 폴더는 'deskG/개선점'(id 4)에 두면 될까요? 다른 데가 맞으면 알려주세요.
```

판단 기준: **"이건 진전인가, 아니면 그냥 한마디인가?"** 진전이면 2), 한마디면 3).
코멘트는 남발하지 않는다 — 알림이 매번 태스크 작성자에게 간다.

## 4) 완료 — 마무리 코멘트 (평문)

작업이 끝나면. `done.txt`로 저장 후 `comment`:

```
✅ 완료

한 일
• …
• …

결과 · 검증
• … (실제로 확인한 증거 위주)

커밋
• <요약> — https://deskg.kr/72   (커밋 첫 줄에 태스크 링크)
```

- 상태(시작전/진행 중/검수중/완료)·완료 체크는 `patch` 로 바꾼다:
  `patch 72 --status 완료 --done true`. 구버전 서버라 `patch` 가 404면 완료를 **본문에
  분명히** 적고, 상태 전환은 사람이 UI에서 한다.
- 필요하면 사용자에게 "제가 완료 코멘트까지 올릴까요?"처럼 **쓰기 전에 확인**한다.

### 스크린샷·화면 캡처를 함께 올릴 때

증거가 되는 화면(스크린샷·그래프·before/after)은 말로 설명하는 것보다 이미지가 낫다.
`photo-upload` 로 올린 뒤 반환된 `url`을 본문 HTML에 넣는다(코멘트는 평문이라 이미지 불가):

```bash
python "<스킬>/scripts/deskg.py" photo-upload after.png     # → <img src="/uploads/…"> 안내 출력
```
```html
<h3>결과</h3>
<p>목록 초기 렌더가 1.8s → 0.4s.</p>
<img src="/uploads/8f1c….png" alt="개선 후 로딩 타임라인">
```
이 HTML을 `--html-file` 로 `progress`(새 버전) 또는 `new`(계획)에 넘긴다.
이미지 여러 장이면 `<img>` 사이에 무슨 화면인지 한 줄씩 설명을 넣는다 — 나중에 읽는 사람이
캡션 없는 이미지 나열을 해석하지 못한다.

## 흔한 실수

- 코멘트에 HTML/마크다운 표를 넣기 → 평문이라 글자로 보인다. 불릿·줄바꿈으로.
- 사소한 것마다 "진행 추가" → 코멘트만으로 충분한지 먼저 판단.
- 관련 태스크 검색 없이 새 태스크 생성 → 중복. 항상 `tasks --q` 먼저.
- 최상위/폴더보유 폴더에 생성 시도 → 400. `folders`로 leaf 폴더 확인.
- 커밋 첫 줄에 태스크 링크 누락 → 커밋↔태스크 추적이 끊긴다.
